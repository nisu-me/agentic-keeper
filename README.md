# agentic-keeper

**What your agent learns dies with the session.** Your AI coding agent learns things every
session (gotchas, decisions, the *why* behind the code) and forgets all of it when the session
ends. The keeper fixes that with enforcement: a repo-committed knowledge base your agent is
mandated to maintain, and a Stop hook that **holds the agent's turn open** until new knowledge is
captured or explicitly declined.

## Install: hand this to your agent

```
Set up the "keeper" system in this repo, using
https://github.com/nisu-me/agentic-keeper.
Fetch REPLICATE.md from that repo first and follow it: ask me the
questions it lists, adapt the config to this codebase, copy the core
files verbatim, and run its verification checklist before you call
the setup done.
```

The prompt tells your agent to follow a document from this repo, so read
[REPLICATE.md](REPLICATE.md) and the [hooks](.claude/hooks/) first.

That's the whole installer. No package, no plugin — the repo is its own installer, and your agent
adapts it to your codebase (any language: the keeper reads file paths and markdown, never your code).

Run the install with a strong model at high reasoning effort. It's a one-time job with real judgment
calls — which paths are load-bearing, whether to migrate what your CLAUDE.md already knows. Everyday
sessions don't need it.

## What you get — the loop

1. **Inject** — a SessionStart hook feeds the KB index + keeper mandate into every session (6 lines of context, zero exploration cost).
2. **Place** — a placement-rules table: "you have X → it goes to Y → via skill Z". Filing fails when the writer has to decide where things go; the table decides.
3. **Capture** — `/capture` (facts) and `/adr` (decisions) file knowledge the turn it lands.
4. **Enforce** — at turn-end the Stop hook checks what the session edited and what *you* said: knowledge-bearing code edited without docs? decision language in your chat messages? bulk session with zero docs impact? → the agent isn't allowed to wrap up yet: it keeps going until it files the knowledge or explicitly states `Knowledge check: nothing to record — <why>` (it asks at most twice). It never refuses *you*; it holds the agent's turn open. Each signal fires once per occurrence; any KB edit silences the session. Blanket every-turn nags get switched off — targeted ones don't.
5. **Repair** — `/docs-audit` runs deterministic drift checks (index completeness, link resolution, ADR numbering).

**You distill the keeper, not the knowledge.** The machinery transfers; your gotchas and ADRs are
yours, accumulated in your repo, reviewable like code.

## Before you trust it

The hooks execute on your machine — [read them first](.claude/hooks/); they're ~340 lines total,
dependency-free Node, and every failure path exits 0 (a broken hook can never wedge a session).
Escape hatch: `KEEPER_OFF=1`. The keeper holds the turn at most twice in a row (the nudge, then one check for
the explicit "no"), and the platform itself caps consecutive Stop-hook continuations at 8 — the keeper
can insist; it cannot hold you hostage.

The keeper also tests itself: `node scripts/keeper-check.smoke.mjs .claude/hooks/keeper-check.mjs`
fires synthetic fixtures at all three signals, the fail-safe guards (`stop_hook_active`,
`KEEPER_OFF`, unreadable transcript), the silence cases, root-anchored KB matching, pasted-log
filtering, the PostToolUse edit log, the on-disk KB check, and the explicit "no" (already declared → quiet; missing → one follow-up) — 17 checks. Append real transcript
paths as extra arguments to also replay format-drift parsing against your own sessions.

## Try it without risking your repo

`demo/` is a tiny todo app with the keeper pre-installed — [ten-minute script inside](demo/README.md):
clone, `cd demo && claude`, paste the feature request, and watch the keeper either stay quiet (the
agent captured the knowledge on its own) or hold the turn until it does. Its keeper setup was generated by an agent following REPLICATE.md — the demo doubles as proof
the replication works.

## Layout

```
.claude/hooks/       session-start.mjs · keeper-check.mjs   (the mechanism)
.claude/skills/      capture · adr · docs-audit             (the filing verbs)
.claude/agents/      docs-reviewer                          (necessity-first KB review)
docs/                README (index + placement rules) · adr/ · knowledge/ · conventions/ · runbooks/
scripts/             keeper-check.smoke.mjs                 (the self-test)
demo/                todo app with the keeper pre-installed (via REPLICATE.md — the proof)
REPLICATE.md         the spec your agent follows to install this into YOUR repo
```

## What it doesn't do

- *Code* edited through shell commands (`sed -i`, `cat >`) isn't seen as a knowledge-path edit — only Edit/Write/MultiEdit/NotebookEdit are. (KB files written by shell *are* caught, by file modification time.) Edits made inside subagents are caught too: Claude Code runs your PostToolUse hooks inside subagents, so they land in the same edit log.
- The conversation markers are English-only (one regex to adapt).
- The explicit "no" is a text line. The hook checks that it's there, not that it's true — the `<why>` is visible in the transcript, and KB diffs go through code review.
- It governs agent sessions only; humans get convention and code review.

Works with Claude Code (reference). Codex CLI's Stop hook continues the turn the same way; Gemini's
`AfterAgent` can force a retry; Cursor's `stop` can only send a follow-up — honest port notes in
[REPLICATE.md §5](REPLICATE.md).
